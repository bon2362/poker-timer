## Архитектура

Next.js 16 App Router + TypeScript + Tailwind CSS + Supabase Realtime.
Настройки хранятся в `localStorage` (ключ `pokerTimerConfig`).
Компоненты в `components/`, логика в `lib/` и `reducer/`, типы в `types/`.

## Деплой

Автоматический: каждый `git push` в `main` → GitHub Actions (`.github/workflows/test.yml`) прогоняет юнит-тесты и деплоит через `vercel deploy --prod`. Деплои из Git-интеграции Vercel отменяются сразу (Ignored Build Step = `exit 0`) — это нормально. Вручную CLI не нужен.

## Бэклог

Issues в репозитории + GitHub Projects. Добавлять задачу:

gh issue create --repo bon2362/poker-timer --title "..." --body "..."

## Автотесты

Баг на проде некритичен, владелец проверяет каждую фичу руками после релиза. Тесты нужны только чтобы раньше ловить регрессии при разработке.

- Покрываем: логику таймера и блайндов (`reducer/`, `lib/`), синхронизацию между устройствами (`context/`), серверные запросы с данными и авторизацией (`app/api/`), расчёты призовых и ребаев.
- Не покрываем: CSS-классы, цвета, тексты, «элемент отрисовался», открытие модалок — это видно при ручной проверке.
- Не прописывать в тестах номер версии и другие значения, которые меняются каждый релиз.
- К фиче — максимум 1–3 теста на её логику. Тесты ради процента покрытия не писать.
- E2E (`e2e/`) — только дымовой минимум главного пути; новые добавлять лишь для того, что нельзя проверить юнит-тестом. E2E в CI не блокируют деплой, деплой ждёт только юнит-тесты.
- E2E работают с отдельным Supabase-проектом `poker-timer-test` (ref `eeoqtxticjzzwlbqytnc`), не с продом. Playwright сам поднимает локальный сайт на порту 3100; ключи берутся из `.env.test.local` (локально) или секретов `TEST_SUPABASE_*` (CI). Перед прогоном `e2e/global-setup.ts` очищает тестовую базу; на прод-проект он отказывается работать. Без ключей сайт в e2e работает без Supabase.
- После изменения схемы прод-базы повторить её в тестовой: `supabase db dump --linked --schema public` и применить к `poker-timer-test`. Бесплатный проект засыпает после 7 дней без запросов — тогда разбудить его в панели Supabase.

## Версионирование

Текущая версия: **6.24**

Версия отображается в шапке админки (`components/admin/VersionBadge.tsx`), история версий хранится в `components/SettingsScreen.tsx`.

**Правила:**
- При каждом изменении кода автоматически увеличивать минорную версию: 4.0 → 4.1 → 4.2 и т.д.
- Мажорную версию поднимать только по явной просьбе пользователя: 4.x → 5.0
- После изменения версии обновлять её в этом файле (строка «Текущая версия»)
- При добавлении новой фичи добавлять запись в массив `CHANGELOG` в начале `components/SettingsScreen.tsx` — новая версия вставляется первой в массиве
